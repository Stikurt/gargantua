# Экспериментальная генерация: API и консоль

Этот документ описывает сохранённый сервер ветки `experimental/audio`. Он относится к cookie/CSRF API старого клиента, а не к `/api/mvp` стабильной ветки. [Установка](../../SETUP_AUDIO.md) и [приёмка с ограничениями](../../TESTING_AUDIO.md) опубликованы отдельно; сырые частные отчёты и пользовательские библиотеки не входят в репозиторий.

## Доступ

Все маршруты требуют сессии профиля. Изменения требуют `X-Cotology: 1`, актуального `X-CSRF-Token` и допустимого Origin. Читатель без права автоматического импорта ждёт решения владельца. Сервер повторно проверяет разрешения во время работы и выдачи готового результата. Получение существующего разрешённого результата и право запускать новую дорогую задачу учитываются отдельно.

Клиент не передаёт Docker-команды, пути, image ID или произвольные модели. Профили и рецепты выбираются сервером из закреплённого списка. Сервер и модельный исполнитель не предназначены для публичного анонимного доступа.

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/derived/profiles` | Языки и закреплённые профили |
| `POST /api/derived/requests` | Запрос перевода или озвучки |
| `GET /api/derived/requests?limit=50` | Доступные профилю заявки |
| `GET /api/derived/requests/:id` | Заявка, работа и checkpoint-прогресс |
| `POST /api/derived/requests/:id/decision` | `approve`, `cancel`, `retry` с актуальным `expectedRevision` |
| `GET /api/derived/jobs/:id/result` | Проверенный манифест готового результата |
| `GET /api/derived/jobs/:id/audio/segments/:ordinal` | PCM WAV, одиночный HTTP Range и ETag |
| `GET /api/derived/jobs/:id/segments/:ordinal` | Один текстовый или звуковой фрагмент |

## Создание заявки

UUID берутся из собственной библиотеки, а `idempotencyKey` создаётся клиентом один раз на намерение. Пример для русской книги:

```json
{
  "idempotencyKey": "10000000-0000-4000-8000-000000000001",
  "kind": "audio",
  "publicationIds": ["20000000-0000-4000-8000-000000000002"],
  "sourceLanguage": "ru",
  "audio": false,
  "chapterRange": {"start": 1, "count": 5}
}
```

Для перевода: `kind:"translation"`, `sourceLanguage:"en"`; `audio:true` дополнительно запрашивает озвучку русского результата. Поле `audio` при `kind:"audio"` не означает загрузку на телефон: это только серверная работа. `glossary` перевода содержит до 30 пар длиной до 80 символов на сторону. Опциональные `snapshotId` и упорядоченные `publicationIds` должны точно соответствовать доступному снимку источника; первая часть не заменяет всю новеллу. `discoveryRequestId` связывает запрос только с точным разрешённым источником готовой поисковой заявки.

Повтор того же ключа с тем же телом возвращает прежнюю заявку, другое тело с тем же ключом даёт конфликт. Разные заявки на идентичный источник и рецепт могут переиспользовать одну работу. Отмена подписки одного профиля не отнимает готовый разрешённый результат у остальных.

## Главы и продолжение

`chapterRange.start` начинается с 1. По умолчанию выбираются первые пять доступных глав; перевод ограничен пятью главами на запрос, прямое русское аудио — пятьюдесятью. Только последний пакет уменьшается по фактическому концу источника. Выбранные публикации, локаторы глав и диапазон участвуют в immutable source v2 и идентичности работы. Старые source v1 и подтверждённые checkpoints не переписываются новым default.

Публичный статус может содержать:

```json
{
  "chapterRange": {"start": 1, "count": 5, "total": 275, "hasMore": true, "nextStart": 6},
  "partial": true
}
```

Это готовность выбранного пакета. Для следующих глав создаётся новый явный запрос с прежним исходным снимком и следующим диапазоном; автоматической генерации всех последующих глав нет. Пакет 6–10 не подменяет 1–5. После перевода `chapterRange` может описывать короткую русскую публикацию, а `originChapterRange` — её исходные главы. Для продолжения используется исходная заявка перевода, а не номер главы внутри короткого русского результата.

## Результат, восстановление и ресурсы

Перевод публикуется отдельно от оригинала со своим происхождением и отметкой `machine-draft`; аудио имеет отметку `technical-unlistened`. Исходные байты, позиции чтения и изображения оригинала не заменяются. Проверяются входной SHA, рецепт, роль, lease/permit, формат выхода и антивирус; файл сохраняется до checkpoint в PostgreSQL. После перезапуска вычисляется незавершённый сегмент, а принятый префикс проверяется по хешам. Частичная книга или неполный набор сегментов не объявляются завершённым результатом выбранного пакета.

Манифест содержит порядок, SHA-256, размеры и длительности; внутренние файловые пути и lease tokens не выдаются. Готовность серверной работы не означает, что всё скачано в клиент. Клиент отдельно проверяет и сохраняет все фрагменты для автономного воспроизведения. Позиции текста и аудио независимы.

Один тяжёлый слот обслуживает импорт/генерацию. TTS-контейнер ограничен 2 ГиБ/2 CPU; переводчик — 5 ГиБ/6 CPU с GPU, плюс вспомогательный клиент. Модель загружается заново для каждого ограниченного сегмента, поэтому короткий пилотный RTF не является обещанием скорости полной книги. Сегмент исходного текста — до 700 символов; WAV исполнителя — до 8 МиБ и 180 секунд. PCM16 mono 22050 Hz занимает около 151 МиБ/час. База, антивирус и прочие службы расходуют ресурсы дополнительно.

Неизвестные/просроченные метрики останавливают выдачу тяжёлой работы. Для GPU действуют мягкая пауза с 80°C, возобновление после охлаждения до 65°C и жёсткая остановка с 87°C. Неизвестная остановка контейнера не освобождает слот для следующей модели. Полная антивирусная аттестация весов и проверка качества голоса на слух не заявляются: `NOT_FULLY_SCANNED` и `NOT_LISTENED` сохраняются.

## Административная консоль

```powershell
docker compose exec -T app node server/cli.mjs derived profiles
docker compose exec -T app node server/cli.mjs derived request <book-id> --audio --source-language ru
docker compose exec -T app node server/cli.mjs derived request <book-id> --translate --source-language en --no-audio
docker compose exec -T app node server/cli.mjs derived list
docker compose exec -T app node server/cli.mjs derived show <request-id>
docker compose exec -T app node server/cli.mjs derived approve <request-id> <revision>
docker compose exec -T app node server/cli.mjs derived cancel <request-id> <revision>
docker compose exec -T app node server/cli.mjs derived retry <request-id> <revision>
docker compose exec -T app node server/cli.mjs derived result <job-id>
```

`--key <UUID>` позволяет повторить создание после потерянного ответа. Все команды консоли выполняются с правами администратора собственной установки. Порядок запуска и штатной остановки исполнителя указан в инструкции установки; исторические обёртки с отсутствующим переносимым runtime не заменяют эти шаги.
