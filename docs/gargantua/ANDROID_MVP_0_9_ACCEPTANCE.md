## Границы безопасности и надёжности

Нативный импорт проверяет пути ZIP, структуру, размеры и SHA-256 всех включённых разделов до публикации текста в хранилище. Совпадающие исходные главы используются повторно. При другом содержимом того же ключа импорт отклоняется с `CATALOG_CONFLICT`; прежний текст не заменяется. Нативные тексты импортируются одной транзакцией. Создание книжных карточек и папки выполняется затем в хранилище интерфейса; это не одна общая транзакция двух хранилищ. При ошибке записи папки приложение пытается убрать новые карточки; прежние издания и общий текст сохраняются.

Экспорт включает только уже сохранённые главы и может быть частичным. Файл не содержит конфигурацию сервера, личные закладки и место чтения. Пределы формата: 1000 книг / 50 000 разделов / 8 МиБ описания / 24 МиБ на раздел / 512 МиБ ZIP / 1 ГиБ распакованных данных. В Android-сохранении и системном меню отправки используется имя вида `Название.gargantua.zip`.

Служба использует уведомление и ограниченный wake lock во время активной работы. Android и производитель устройства сохраняют право остановить её; после принудительной остановки или перезапуска телефона нужно повторно открыть приложение. Автоматический запуск при включении телефона и обход энергосбережения не реализованы. Поиск и недостающие главы по-прежнему требуют сервера; файл с уже сохранёнными текстами читается автономно.

## Воспроизведение и дальнейшее заполнение

Сначала установите собранный APK и настройте своё обычное подключение. Автоматизация использует ADB и Playwright; серийный номер устройства передаётся явно через `--serial`, здесь персональные параметры не приводятся.

```powershell
node --test tests/mvp-library-organization.test.mjs tests/mvp-catalog-transfer.test.mjs
node --test tests/warriors-download-script.test.mjs
node scripts/test-mvp-android-library-refresh.mjs --plan true
node scripts/test-mvp-android-catalog-transfer.mjs --plan true
node scripts/test-mvp-desktop-library.mjs --plan true
node scripts/download-warriors-android.mjs --plan true
```

Текущие сценарии: `scripts/test-mvp-android-library-refresh.mjs`, `scripts/test-mvp-android-catalog-transfer.mjs`, `scripts/test-mvp-desktop-library.mjs`, `scripts/download-warriors-android.mjs`. Требования к существующей библиотеке, режимам сохранения службы и тестовым профилям перечислены в [методике](../TESTING.md#воспроизведение). Старый Android background-harness в публикацию 0.9 не включён: его селекторы прежних папок устарели. Его результаты выше сохранены как исторические доказательства с собственными SHA, а не как команда повторного запуска на текущем интерфейсе.

Сценарий списка серии сохраняет контрольные точки, различает отсутствие результата и сбой источника и не объявляет постановку в очередь полной загрузкой. Необязательный `--batch-size 8` позволяет ставить найденные книги в очередь после каждых восьми позиций списка и продолжать поиск остальных; окончательный отчёт отдельно проверяет порядок всех выбранных книг и фактические счётчики загрузок. Параметр `--discover-ids ID1,ID2` ограничивает только повторный поиск: полный порядок и сводка остаются по 116 позициям, а отчёт явно перечисляет записи, посещённые именно в этом запуске. Его нельзя сочетать с `--limit`. Уже активные задания и их срок ожидания источника сохраняются без повторной постановки в очередь.

Сырые доказательства хранятся локально; они могут содержать персональные сведения и не предназначены для публикации без обезличивания. По мере проверки книжной очереди отчёт следует обновлять её фактическими результатами. При смене APK результаты следует связывать с контрольной суммой проверенной сборки.
