# Установка и запуск Гаргантюа

Текущие исходники: Windows и Android **0.9.0**, сервер **0.7.1**. Команды PowerShell выполняются в корне клона. Для сервера также подходят Linux и macOS с Docker Compose; клиентские PowerShell-сценарии проверялись на Windows.

## Требования

| Задача | Что установить |
|---|---|
| Клонирование | Git |
| Сервер | Docker Engine / Docker Desktop с Compose v2; Linux containers |
| Windows-клиент | Windows x64, PowerShell 5.1 или новее, Docker Desktop, закреплённый архив Electron |
| Сборка Android | Docker, PowerShell; SDK и JDK устанавливаются внутри образа сборки |
| Установка/проверка Android | Android 10+, актуальный Android System WebView, Android Platform Tools (`adb` в PATH), USB-кабель с передачей данных |
| Удалённое подключение телефона | Tailscale на ПК и телефоне, одна доступная обоим сеть Tailscale |
| Тесты без Docker и клиентская автоматизация | Node.js 24 и npm; дополнительно Playwright для сценариев интерфейса |

Для первого скачивания образов, npm/Gradle-зависимостей и SDK нужен интернет. Сборка Android ограничена сценарием двумя процессорами и 3 ГБ памяти контейнера; самому Docker и ОС нужна дополнительная память и свободное место. Сервер ограничен 512 МБ памяти и двумя процессорами. Эти лимиты не являются измерением минимальных требований или гарантией работы на любом устройстве.

## Готовые файлы

Готового GitHub Release **0.9 пока нет**; новая версия собирается из `main` по следующим разделам. [Предыдущий Release v0.8.0](https://github.com/Stikurt/gargantua/releases/tag/v0.8.0) содержит прежние Windows ZIP, APK и SHA256SUMS.txt. Обновление исходников не заменяет эти бинарные файлы.

ZIP Windows распаковывается целиком; Android APK устанавливается обычным системным установщиком или `adb install -r <путь-к-APK>`. На устройстве может потребоваться разрешение на установку из выбранного источника. Сервер поднимается отдельно по инструкции ниже. Для обновления Android нужна прежняя подпись; не удаляйте приложение с библиотекой автоматически.

## Получение исходников

```powershell
git clone https://github.com/Stikurt/gargantua.git
cd gargantua
```

 Для обычной установки используйте ветку `main`. Для озвучки предназначена отдельная ветка `experimental/audio` с собственными инструкциями и требованиями к ресурсам.

Для команд ниже секреты и `.env` не нужны. Личные адреса сервера вводятся только на вашем устройстве и не должны попадать в коммиты и публичные отчёты.

## Сервер

Запустите Docker Desktop и дождитесь готовности Linux engine. Затем:

```powershell
docker version
docker compose version
docker compose up -d --build
docker compose ps
Invoke-RestMethod http://127.0.0.1:3080/api/mvp/health
```

Ответ проверки содержит `ok: true`, `version: 0.7.1`, `mode: search-offline-reader`. После первого запуска контейнеру может потребоваться несколько секунд для перехода в состояние `healthy`.

Поиск и получение новых глав требуют интернета **на сервере**. Сервер работает одним контейнером, не запускает PostgreSQL, TTS или автоматическое резервирование. Книги сохраняет клиент, а не Docker. Серверный `127.0.0.1:3080` доступен только самому ПК; `0.0.0.0` внутри контейнера не означает открытие порта во внешнюю сеть.

В браузере этого ПК можно открыть `http://127.0.0.1:3080`. Хранилище браузера отдельное от Windows-приложения и телефона. Для дальнейших сценариев приёмки используются именно приложения.

Если нужен только сервер для Android, на этом этапе Windows-клиент собирать не требуется.

## Сборка и запуск Windows

Сценарий сборки использует заранее скачанный архив Electron. В свежем клоне подготовьте его из закреплённой записи `desktop/runtime.json`:

```powershell
$runtime = Get-Content .\desktop\runtime.json -Raw | ConvertFrom-Json
$runtimeDirectory = Join-Path (Get-Location).Path '.local/electron-cache'
New-Item -ItemType Directory -Force -Path $runtimeDirectory | Out-Null
$runtimeArchive = Join-Path $runtimeDirectory ('electron-v' + $runtime.version + '-win32-x64.zip')
if (-not (Test-Path -LiteralPath $runtimeArchive)) {
    Invoke-WebRequest -UseBasicParsing -Uri $runtime.source -OutFile $runtimeArchive -TimeoutSec 300
}
$actualRuntimeHash = (Get-FileHash -LiteralPath $runtimeArchive -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actualRuntimeHash -ne $runtime.sha256) { throw 'SHA-256 Electron не совпал. Не используйте этот архив.' }
.\scripts\build-mvp.ps1
.\scripts\run-mvp.ps1
```

`build-mvp.ps1` собирает Docker-образ и копирует в Windows-приложение интерфейс из него. Архив Electron проверяется по SHA-256 повторно. Если проект уже собран, для обычного запуска достаточно:

```powershell
.\scripts\run-mvp.ps1
```

Приложение: `releases/Gargantua-MVP/Gargantua.exe`. Для копирования на другой Windows x64 перенесите **всю** папку `Gargantua-MVP`: исполняемый файл зависит от соседних файлов Electron и `resources/app`. Для поиска на новом ПК отдельно запустите сервер. Windows-клиент обращается к локальному серверу `http://127.0.0.1:3080`; настройка удалённого сервера в Windows-клиенте этой версии не реализована.

Перед пересборкой закройте клиент. Подпись Windows-приложения сертификатом издателя не настроена.

## Сборка Android

На Windows с работающим Docker:

```powershell
.\scripts\build-android-mvp.ps1
```

Сценарий:

1. Собирает текущий интерфейс Vite в Docker.
2. Подготавливает образ сборщика Android из `android/Dockerfile`.
3. Копирует в новый Android-модуль только активный интерфейс MVP и сохраняет исходный `native-bridge.js`.
4. Выполняет `:mvp:testDebugUnitTest`, `:mvp:lintDebug`, `:mvp:assembleDebug`.
5. Копирует APK и записывает информацию о сборке.

Результаты:

```text
releases/Gargantua-Android/Gargantua-preview.apk
releases/Gargantua-Android/build-info.json
releases/Gargantua-Android/build-checks.log
```

Сборщик использует Gradle 8.13 / Java 17, Android Gradle Plugin 8.13.0, compile SDK 36, target SDK 35, min SDK 29. JDK, Android Studio и SDK на ПК отдельно не требуются. Сборка не меняет запущенный книжный сервер.

Пакет `local.gargantua.mvp.debug`, версия **0.9.0 / versionCode 2**, подписывается локальным отладочным ключом. Ключ находится в `.local/android-mvp-signing` и не публикуется. Для обновления уже установленного APK нужна та же подпись. Пересборка на другом ПК с новым ключом не сможет заменить старый APK обычным `adb install -r`; удаление приложения удаляет библиотеку и требует отдельного решения владельца устройства. Храните свой ключ локально, если планируете обновления с сохранением данных.

Это отладочный APK с WebView debugging, предназначенный для личной установки и проверки. Ветки и версии приложения не заменяют требования к полноценной магазинной публикации.

## Подключение Android через USB

1. Включите на своём телефоне параметры разработчика и USB-отладку. На некоторых устройствах отдельно требуется разрешить установку по USB.
2. Соедините телефон кабелем с передачей данных, разблокируйте его и подтвердите доверие к своему ПК.
3. Проверьте подключение:

```powershell
adb devices
```

Статус должен быть `device`. `unauthorized` означает, что на телефоне ещё нужно подтвердить запрос; `offline` обычно требует переподключения кабеля. Не меняйте настройки безопасности телефона обходными командами.

4. После сборки сервера и APK выполните:

```powershell
.\scripts\run-android-mvp.ps1 -Install
```

Сценарий устанавливает APK с сохранением данных, запускает существующий серверный образ и настраивает USB-перенаправление `tcp:3080`. В приложение передаётся `http://127.0.0.1:3080` — адрес на телефоне направляется на сервер ПК.

Для повторного запуска без принудительного обновления:

```powershell
.\scripts\run-android-mvp.ps1
```

При нескольких телефонах добавьте `-Serial` с серийным номером из **своего** `adb devices`.

Скачанные главы читаются после отключения кабеля. Новые запросы через USB не работают без кабеля и перенаправления. Для удалённого подключения используйте следующий раздел.

Установка без сценария, если сервер уже готов:

```powershell
adb install -r .\releases\Gargantua-Android\Gargantua-preview.apk
adb reverse tcp:3080 tcp:3080
```

Откройте «Гаргантюа» на телефоне и в настройке сервера укажите `http://127.0.0.1:3080`. Подтвердите системный запрос установки на самом телефоне, если он появился.

## Подключение через Tailscale

Проверено подключение Android к приватному HTTPS Serve поверх мобильной сети. Для настройки используйте **свою** сеть и свой адрес; в репозитории нет персонального домена сервера.

1. Установите Tailscale для Windows и Android. Войдите на обоих устройствах в сеть, где телефон имеет доступ к ПК. При необходимости настройте её разрешения в Tailscale.
2. Запустите книжный сервер:

```powershell
docker compose up -d --build
```

3. Настройте приватный HTTPS на ПК:

```powershell
.\scripts\remote.ps1 enable
```

Сценарий использует Tailscale Serve для `http://127.0.0.1:3080`. Если Tailscale попросит разрешить HTTPS/сертификаты в вашей сети, выполните его подсказку и повторите команду. HTTPS также зависит от настроек DNS/MagicDNS и разрешений вашей сети Tailscale. Сценарий сам не меняет ACL и не открывает роутер.

4. Проверьте готовность:

```powershell
.\scripts\run-tailscale-mvp.ps1
```

Сценарий выводит HTTPS-адрес **этого ПК**, полученный от Tailscale. Он проверяет, что Serve ведёт на порт 3080 и что для адреса не включён публичный Funnel.

5. В Android включите Tailscale, откройте «Гаргантюа», нажмите настройку сервера, введите выведенный HTTPS-адрес и нажмите **«Подключить»**. Нужен только origin без логина, пароля, пути `/api`, параметров и фрагментов.
6. Отключите USB-маршрут, если проверяете именно Tailscale:

```powershell
adb reverse --remove tcp:3080
```

Теперь можно отсоединить кабель и проверить поиск через мобильную сеть. Для поиска и новых загрузок ПК должен оставаться включённым, Docker и Tailscale должны работать. Скачанное читается автономно.

`run-tailscale-mvp.ps1` не подменяет сохранённый адрес телефона. `run-android-mvp.ps1`, наоборот, специально переключает его на USB. После USB-запуска для удалённого режима снова выберите HTTPS в приложении.

Проверка и отключение приватного маршрута:

```powershell
.\scripts\remote.ps1 status
.\scripts\remote.ps1 disable
```

Serve открывает сервер участникам вашей сети согласно её правилам доступа. В MVP нет собственной регистрации и авторизации пользователей; предоставляйте доступ только доверенным устройствам. Публичный Funnel, проброс порта роутера и публикация сервера в интернет этой инструкцией не настраиваются. [Документация Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve).

## Библиотека, фоновые загрузки и файл каталога

В Windows и Android доступны **«Все книги»** и **«Каталоги»**. Локальный поиск учитывает слова названия и автора независимо от порядка, регистра и `ё/е`. Каталоги содержат ссылки на единственную запись книги; повторное добавление не создаёт копию. Порядок каждого каталога сохраняется отдельно. Для операций используйте **«Выбрать»** и общую панель, для перестановки — отдельный значок списка.

В Android **«Скачать целиком»** передаёт очередь отдельной службе с уведомлением. Разрешите уведомления, когда система предложит: через них удобно видеть прогресс и ставить загрузку на паузу. Android и производитель телефона могут ограничить службу; после принудительной остановки или перезагрузки нужно открыть приложение. Автозапуск при включении телефона не реализован. Для новых глав всё время нужен доступный сервер.

Для переноса в Android откройте каталог → **«…» → «Сохранить каталог»** или **«Поделиться каталогом»**. Один файл `Название.gargantua.zip` содержит порядок, оглавления и уже сохранённые главы. Выбор получателя и подтверждение отправки выполняются в выбранном приложении. Чтобы открыть файл, используйте значок открытия в разделе каталогов. Сохранённый локально файл с включёнными текстами импортируется без сервера; облачный провайдер сначала может потребовать сеть для получения самого файла. Это ручной перенос, не синхронизация. Windows-импорт ZIP не реализован.

[Подробное пользование и ограничения файла](gargantua/ANDROID_MVP_0_9_GUIDE.md).

## Хранение данных

| Где | Что хранится |
|---|---|
| Windows: `%APPDATA%/Gargantua-MVP` | Библиотека, тексты, оглавления, очередь, позиции и закладки Electron-клиента |
| Android: приватные данные `local.gargantua.mvp.debug` | Библиотека, каталоги и позиции в хранилище интерфейса; тексты и устойчивая очередь в нативном хранилище; настройки подключения |
| Браузер | Отдельное хранилище конкретного браузера и адреса сайта |
| `.local/electron-cache` | Скачанный архив Electron |
| `.local/android-mvp-signing` | Локальный отладочный ключ Android |
| Docker volume `cotology_android_gradle` | Кэш Gradle для сборки Android |
| `releases` | Сгенерированные программы, журналы и сведения о сборке |

Автоматическая синхронизация библиотек и экспорт книги в EPUB не реализованы. Android-файл каталога — ручной снимок только включённых текстов; личные закладки, место чтения и сервер в него не входят. Полное скачивание сохраняет текст внутри приложения. Очистка данных приложения/браузера или удаление Android-приложения удаляет соответствующую библиотеку. `docker compose down` клиентскую библиотеку не удаляет. Автоматическое резервирование в стабильной ветке не настроено.

## Обновление

Закройте Windows-клиент, сохраните свои локальные данные и ключи обычными средствами владельца устройства. Затем обновите исходники:

```powershell
git pull --ff-only
docker compose up -d --build
.\scripts\build-mvp.ps1 -SkipImageBuild
```

Последняя команда нужна только для Windows-клиента. Убедитесь, что клиент закрыт и архив Electron подготовлен. Для Android:

```powershell
.\scripts\build-android-mvp.ps1
.\scripts\run-android-mvp.ps1 -Install
```

Это USB-обновление переключает адрес приложения на USB. При обычном обновлении APK вручную сохранённый сервер не меняется; при Tailscale после USB-запуска снова выберите HTTPS в настройках приложения. Новая установка должна иметь ту же подпись Android для сохранения данных.

## Остановка

```powershell
docker compose stop
```

Останавливает сервер, сохраняя контейнер. Для удаления только контейнера и сети данного Compose-проекта:

```powershell
docker compose down
```

Для отключения внешнего доступа внутри Tailscale отдельно выполните `scripts/remote.ps1 disable`. Остановка сервера не мешает чтению уже сохранённых глав.

## Диагностика

```powershell
docker compose ps
docker compose logs --tail=100 app
Invoke-RestMethod http://127.0.0.1:3080/api/mvp/health
```

| Симптом | Проверка |
|---|---|
| Docker недоступен | Дождитесь запуска Docker Desktop и Linux engine; проверьте `docker info` |
| Не найден образ / приложение | Сначала выполните сборку сервера и нужного клиента |
| Не найден архив Electron | Выполните подготовку архива из раздела сборки Windows |
| Телефон отклоняет APK | Разблокируйте телефон, подтвердите установку; проверьте разрешение установки по USB и подпись обновления |
| Android через USB не видит сервер | `adb devices`, `adb reverse --list`, здоровье сервера, адрес `http://127.0.0.1:3080` в приложении |
| Tailscale не подключается | ПК включён, оба устройства в доступной сети, Serve настроен, сертификат действителен, адрес в клиенте HTTPS; для этого режима не нужен USB-launcher |
| Часть каталогов не ответила | Смотрите состояние именно этих источников; наличие HTTP 200 с пустым результатом не доказывает наличие искомого издания |
| Загрузка ждёт | Возможны отсутствие сервера, временный сбой или HTTP 429; приложение сохраняет очередь и учитывает `Retry-After` |
| Книга осталась частично скачанной | Проверьте недоступные/ошибочные главы; закрытые источником главы не обходятся и не считаются скачанными |

Перед публикацией собственного отчёта удалите личные домены Tailscale, IP, серийные номера устройств, токены, локальные пути профилей и тексты книг. Сырые журналы автоматизации не предназначены для прямой публикации.
