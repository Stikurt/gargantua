## Методика

Главные сценарии выполнялись через интерфейс собранного Windows EXE и установленного APK на физическом телефоне. Поиск, выбор, объединение, загрузки, закладки и чтение запускались кнопками клиента. Автоматизация не вызывала книжные API в обход клиента, не подменяла ответы источников и не записывала фиктивные данные в хранилище приложения.

Для проверки происхождения использовались журналы штатного транспорта и чтение локальных метаданных/контрольных сумм. Офлайн проверялся блокировкой транспорта конкретного тестового клиента, а для финального Android APK дополнительно физическим удалением USB-маршрута к серверу при выключенном отладочном флаге offline. Отключение транспорта приложения и реальное отсутствие маршрута различаются в результатах.

В репозитории публикуются обезличенные сводные отчёты и сценарии воспроизведения. Сырые локальные журналы, профили, скачанные тексты и персональные сетевые адреса не включены. Сводки не являются полным пакетом сырых доказательств; пользователь может повторить сценарии в своей среде.

Состав выбранного объединения: исходные 1170 записей RanobeLib и дополнение Ranobe.me, в итоге **4531 запись**. Поэтому проверка кэша не доказывает непрерывность произведения при переходе между переводами.

Активная загрузка прерывалась обычным закрытием при 300 подтверждённых разделах и принудительным завершением при 329. ## Воспроизведение

Для модулей достаточно Docker:

```powershell
docker compose up -d --build
docker compose exec -T app npm test
```

Команда внутри контейнера проверяет **123 MVP-теста**, а не дополнительные сценарии серии. Полный набор запускается из клона с Node.js 24:

```powershell
npm ci
npm test
node --test tests/warriors-download-script.test.mjs tests/warriors-download-report.test.mjs
npm run build
```

Для автоматизации клиента установите Playwright в корне клона. Загружать браузеры Playwright не требуется: сценарии присоединяются к Chromium настоящего приложения.

```powershell
npm install --no-save --package-lock=false playwright@1.57.0
```

Сначала соберите приложения по [SETUP](SETUP.md) и запустите сервер. Посмотрите планы актуальных сценариев без подключения к устройствам:

```powershell
node scripts/test-mvp-desktop-library.mjs --plan true
node scripts/test-mvp-android-library-refresh.mjs --plan true
node scripts/test-mvp-android-catalog-transfer.mjs --plan true
node scripts/download-warriors-android.mjs --plan true
```

Windows-сценарий создаёт **отдельный тестовый профиль**, ищет две действительные книги через UI, проверяет каталоги и настоящий холодный запуск. Нормальный клиент перед проверкой должен быть закрыт:

```powershell
node scripts/test-mvp-desktop-library.mjs --exe releases/Gargantua-MVP/Gargantua.exe
```

Для физического Android нужны ADB, явно указанный серийный номер своего устройства и уже установленный APK, совпадающий с переданным файлом. Новые сценарии не устанавливают APK и не очищают данные. Закройте читалку штатно до запуска. Тесты работают с существующей библиотекой и требуют подготовленных данных:

- `test-mvp-android-library-refresh.mjs` требует две полностью скачанные книги Эрин Хантер, восстановимую позицию чтения, название с `ё` в библиотеке и существующий каталог из **52** книг в порядке чтения. Для выбора каталога предусмотрен `--catalog-id`, для изданий — `--books SOURCE:ID,SOURCE:ID`. Это специализированная регрессия принятого состояния, не тест пустой установки. `--cold-restart true` выполняет одну принудительную остановку; без него служба сохраняется.
- `test-mvp-android-catalog-transfer.mjs` требует две уже полностью скачанные книги; по умолчанию «Стань диким!» и «Лес секретов», либо собственные две через `--books` / `--readlist`. Создаёт только свои тестовые каталоги, восстанавливает прежние связи и позиции, сохраняет полученный файл в «Загрузки». `--online true` сохраняет работающую очередь и проверяет отсутствие запросов только выбранных книг; строгий режим по умолчанию включает автономный флаг и принудительные перезапуски.

Для заранее подготовленной библиотеки пример онлайн-проверки переноса:

```powershell
$deviceSerial = 'YOUR_DEVICE_SERIAL'
node scripts/test-mvp-android-catalog-transfer.mjs --serial $deviceSerial --apk releases/Gargantua-Android/Gargantua-preview.apk --online true --malformed true
```

Сценарий `download-warriors-android.mjs` выполняет поиск, выбор, добавление ссылок и постановку в очередь только через UI. Он не устанавливает приложение, не настраивает сервер и не объявляет очередь полной загрузкой. Необязательные `--batch-size 8` и `--discover-ids ID1,ID2` управляют пакетной обработкой и адресным повтором, сохраняя полный список для порядка и сводки. Перед массовым запуском изучите `--plan true` и исходный комментарий сценария.

Старые `test-mvp-client.mjs`, `test-mvp-extensions.mjs`, `test-mvp-downloads.mjs`, `test-mvp-supreme-full.mjs` и `test-mvp-android.mjs` оставлены для исторических сценариев 0.7/0.8. Их ожидания отдельных экранов не принимались заново для интерфейса 0.9; это не рекомендуемый полный прогон новой версии. Прежний Android background-harness не включён в эту публикацию из-за устаревших селекторов папок. Его фактические результаты приведены только как исторические доказательства с SHA.

Новый полный Tailscale-прогон 0.9 не заявляется. Настройка собственного подключения остаётся в [SETUP](SETUP.md#подключение-через-tailscale); личные адреса вводятся локально.

По умолчанию каждый короткий сценарий создаёт новую папку в `.local/test-results`. Выходные JSON, снимки и журналы предназначены для локального анализа. В них могут быть личные адреса и пути; перед публичной отправкой их необходимо обезличить. Сами сценарии используют настоящие сторонние сайты, поэтому изменения каталога или сети могут потребовать пересмотра ожиданий, а не подмены исходных ответов.
