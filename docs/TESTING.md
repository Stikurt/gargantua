# Проверки стабильной основы

Историческая клиентская приёмка выполнена **24 октября 2026**. Сервер и Windows-клиент — 0.7.1, Android — 0.8.0. Ни одна цифра ниже не означает гарантию неизменности внешних каталогов или прохождения всех будущих прогонов.

## Проверка публикационной сборки

Перед выпуском v0.8.0 собрана отдельная чистая копия исходников: Docker/Vite — успешно, модули — **84/84**, Android — **10 Java-тестов**, lint **0 ошибок / 12 предупреждений**, assembleDebug — успешно. Неиспользуемые зависимости прежнего клиента исключены из main; единственное изменение версии среди сохранённых зависимостей — body-parser 2.3.0 → 2.4.0.

Пересобранный Windows EXE прошёл дополнительный клиентский сценарий **80/80**, 16 снимков, 0 ошибок JS/console: «Король в жёлтом» с е/ё, «Коты-воители», чтение, закладка, холодный запуск и автоматическое возвращение офлайн, размеры 1280×800 и 900×650. Книжные действия выполнялись только через интерфейс; сервером служил уже принятый 0.7.1. Офлайн этого прогона — блокировка транспорта изолированного профиля клиента. Большая загрузка тысяч глав повторно при упаковке не запускалась.

APK в GitHub Release — **исходный принятый файл** с SHA, указанным ниже, а не новая пересборка с другим отладочным ключом. Публикационная пересборка подтверждает сборку из исходников; её установка на телефон не заявляется. [Машиночитаемая обезличенная сводка](reports/acceptance-summary.json).

## Методика

Главные сценарии выполнялись через интерфейс собранного Windows EXE и установленного APK на физическом телефоне. Поиск, выбор, объединение, загрузки, закладки и чтение запускались кнопками клиента. Автоматизация не вызывала книжные API в обход клиента, не подменяла ответы источников и не записывала фиктивные данные в хранилище приложения.

Для проверки происхождения использовались журналы штатного транспорта и чтение локальных метаданных/контрольных сумм. Офлайн проверялся блокировкой транспорта конкретного тестового клиента, а для финального Android APK дополнительно физическим удалением USB-маршрута к серверу при выключенном отладочном флаге offline. Отключение транспорта приложения и реальное отсутствие маршрута различаются в результатах.

В репозитории публикуются обезличенные сводные отчёты и сценарии воспроизведения. Сырые локальные журналы, профили, скачанные тексты и персональные сетевые адреса не включены. Сводки не являются полным пакетом сырых доказательств; пользователь может повторить сценарии в своей среде.

### «Верховный Маг»

Состав выбранного объединения: исходные 1170 записей RanobeLib и дополнение Ranobe.me, в итоге **4531 запись**. Скачаны **4525 доступных разделов**; каждый открыт через настоящую читалку без сервера, проверены собственный источник и SHA-256 отображаемого текста. Запросов `/chapter` при офлайн-чтении — **0**. Все **4555 выполненных проверок** успешны, 0 ошибок JS/console.

| Источник раздела | В оглавлении | Сохранено и открыто офлайн | Недоступно |
|---|---:|---:|---:|
| RanobeLib | 1170 | 1164 | 6 |
| Ranobe.me | 3361 | 3361 | 0 |
| Всего | 4531 | 4525 | 6 |

**Полная загрузка 4531/4531 не достигнута.** Общий `ok` исходного большого отчёта оставлен `false`; `completedAccessible: true` означает только успешную проверку доступных разделов. Клиент отображает частичную загрузку.

Закрыты источником RanobeLib: `v8-c800`, `v10-c1151`, `v10-c1152`, `v10-c1153`, `v10-c1154`, `v10-c1155`. Ограничения доступа не обходились. Совпадение номера в другом переводе не считается доказательством совпадения текста: при сопоставлении заголовков обнаружен сдвиг преимущественно на пять глав. Поэтому проверка кэша не доказывает непрерывность произведения при переходе между переводами.

Активная загрузка прерывалась обычным закрытием при 300 подтверждённых разделах и принудительным завершением при 329. Подтверждённые записи сохранились, при следующем запуске очередь продолжилась автоматически, повторного скачивания этих записей не было. Дополнительные завершившиеся запросы успели сохранить ещё по два раздела. Реальный HTTP 429 привёл к ожиданию более 60 секунд и снижению частоты именно для ограничившего источника; пауза пережила перезапуск.

Этот большой прогон выполнялся на Windows. Он не выдаётся за проверку 4531 раздела на Android.

Финальный APK обновлён без очистки библиотеки, установленный файл независимо выгружен и побайтно сверён с указанным выше итоговым APK.

На финальном APK USB-маршрут к серверу действительно удалён, отладочный offline-флаг **выключен**. Промежуточные диагностические сбои сценария также не скрываются: автоматически восстановленная читалка мешала ожиданию нижней навигации; завершённая очередь не отправляла ожидаемый тестом `/health`; временный `mCurrentFocus=null` ошибочно считался переходом в браузер. Сценарии уточнены, итоговые функции проверены отдельными прогонами без очистки данных пользователя.

## Android через Tailscale

На том же итоговом APK: **81/81 утверждение**, 54,4 секунды, 13 снимков, 6 запусков, 0 ошибок WebView/console. Телефон использовал Tailscale поверх мобильной сети. USB служил только управлению тестом и чтению экрана; переадресация книжного порта `tcp:3080` отсутствовала при каждом запуске.

Адрес введён через настоящий нативный диалог подключения и сохранён после холодных запусков; тест не передавал его через отладочный параметр запуска. Использован приватный Serve с обычной проверкой HTTPS-сертификата Android. Личный адрес не публикуется.

Через интерфейс снова найдены «Король в жёлтом» и «Стань диким!» по запросу «Коты-воители». Свежая книга «Пять сантиметров в секунду: Другая сторона» из RanobeLib ранее не была скачана на телефон:

- Получены все три раздела: **3/3**, суммарно 331 593 символа отображаемого текста.
- Пауза на **2/3** сохранилась после принудительного закрытия и холодного запуска.
- Активная очередь продолжилась после нового запуска; два сохранённых раздела повторно не запрашивались.
- Все **3/3** открыты из кэша с совпадением хешей и источника, именованная закладка сохранилась.

На офлайн-этапе этого Tailscale-сценария блокировался нативный транспорт приложения; VPN и системная сеть телефона продолжали работать. Проверка с реально отсутствующим маршрутом к серверу отдельно выполнена для 25 разделов финального APK, как описано выше.

Первый диагностический запрос «Она и её кот» вернул пустой результат RanobeLib при HTTP 200. Этот прогон не считается успешно завершённым и не заменён фиктивной карточкой. Для полной загрузки использован найденный в действительном каталоге результат другого запроса. Наличие любой книги в любом каталоге не гарантируется.

## Воспроизведение

Для модулей достаточно Docker:

```powershell
docker compose up -d --build
docker compose exec -T app npm test
```

Для автоматизации клиента установите Node.js 24 и Playwright в корне клона. Загружать браузеры Playwright не требуется: сценарии присоединяются к Chromium настоящего приложения.

```powershell
npm ci
npm install --no-save --package-lock=false playwright@1.57.0
```

Сначала соберите нужные приложения по [SETUP](SETUP.md) и запустите сервер. На Windows:

```powershell
node scripts/test-mvp-extensions.mjs --sections books,novels
node scripts/test-mvp-extensions.mjs --sections hub
node scripts/test-mvp-downloads.mjs --sections normal,merged
```

Для большого прогона с сохраняемым тестовым профилем:

```powershell
node scripts/test-mvp-supreme-full.mjs --output .local/test-results/supreme-repeat --resume true
```

Это длительная реальная загрузка тысяч разделов. Она зависит от доступности источников и их ограничений частоты. Сценарий сохраняет контрольные точки; повторная та же команда продолжает проверку. Исторические 4531/4525/6 относятся к зафиксированному оглавлению, а не навсегда закреплённому каталогу.

Для физического Android подключите один авторизованный телефон, соберите APK и запустите USB-клиент. Тест обновляет отдельный пакет MVP, создаёт тестовые книги в его библиотеке и принудительно перезапускает его; данные приложения не очищаются. Если подключены несколько устройств, добавьте `--serial` с номером своего телефона.

```powershell
node scripts/test-mvp-android.mjs --sections layout
node scripts/test-mvp-android.mjs --sections books,normal,merged
node scripts/test-mvp-android.mjs --sections disconnected
node scripts/test-mvp-android.mjs --sections external,random
```

Для Tailscale сначала настройте Serve и убедитесь, что телефон подключён к своей сети. В примере замените `https://YOUR-PC.YOUR-TAILNET.ts.net` адресом **своего ПК**:

```powershell
node scripts/test-mvp-android.mjs --profile tailscale --server https://YOUR-PC.YOUR-TAILNET.ts.net --sections tailscale
```

Этот сценарий не создаёт USB-маршрут книжного порта. USB всё равно нужен для ADB/CDP и снимков физического устройства. Для запусков без повторной установки допустим `--skip-install true`: сценарий проверит совпадение установленного APK с локальным файлом.

По умолчанию каждый короткий сценарий создаёт новую папку в `.local/test-results`. Выходные JSON, снимки и журналы предназначены для локального анализа. В них могут быть личные адреса и пути; перед публичной отправкой их необходимо обезличить. Сами сценарии используют настоящие сторонние сайты, поэтому изменения каталога или сети могут потребовать пересмотра ожиданий, а не подмены исходных ответов.
