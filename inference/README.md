# Изолированный локальный обработчик

`profiles.json` — выбранные фиксированные профили и их SHA256 для БД. `profiles.lock.json` — точные runtime IDs и допущенные модельные файлы. EN→RU использует Qwen3.5 4B Q4; русская озвучка — Piper Denis FP32/Sherpa CPU. Веса не прошли полное антивирусное сканирование: `NOT_FULLY_SCANNED`; используются отдельно проверенные происхождение, хеши и форматы. Лимит сканера книг не увеличивается. Перевод обозначается машинным черновиком; технически корректный звук не равен прослушанному.

Хост запускается скрыто через `scripts/derived-executor.ps1 -Action start`, останавливается через `-Action stop`, состояние — `-Action status`. Docker Desktop должен уже работать. Серверный worker остаётся единственным планировщиком тяжёлых задач. Хост читает свежие решения существующего монитора ресурсов и дополнительно RAM, диск и для GPU-перевода температуру. CPU-озвучка не требует доступной GPU.

Для каждого сегмента worker атомарно сохраняет `.local/inference-spool/incoming/<attempt UUID>/input.json`, затем обновляет `permit.json` каждые 5 секунд. Permit строго содержит `schemaVersion:1`, `jobId`, `segmentId`, `attemptId`, `expiresAt` (epoch ms, максимум 30 секунд вперёд). Запрос содержит все те же идентификаторы, `kind:translation|tts`, `profile`, `profileSha256`, `recipeSha256`, `inputSha256`, `text`, `sourceLanguage`, `targetLanguage`, необязательные `previousSourceContext` и `glossary`. `recipeSha256` — идентичность полной серверной рецептуры, хост её только возвращает; она не выбирает код, пути или runtime. `requestSha256` — SHA256 точных исходных байтов input.json, не повторной сериализации JSON.

Один сегмент — максимум 700 символов Unicode. Контекст — только два предыдущих исходных сегмента до 600 символов каждый; словарь — максимум 30 пар до 80 символов на сторону. До перевода штатный `/v1/chat/completions/input_tokens` считает токены тем же chat-template; вход 1152 + выход 768 + резерв 128 помещаются в 2048. Превышение возвращает `needs_split`, без обрезания. Контекст сдвигать запрещено. Неполный перевод при лимите выхода не публикуется. Для TTS сохраняется исходный текст без недоказанной нормализации; PCM ограничен 180 секундами и 8 MiB на сегмент.

Модельный контейнер получает только копию одного input.json, код, выбранные веса read-only и отдельный временный каталог результата. Корень read-only, сеть none, пользователь 1000, capabilities удалены, нет Docker socket, портов, DB, библиотеки и остальных заданий. Loopback-клиент переводчика находится внутри того же закрытого сетевого пространства. Client/TTS имеют kernel-лимит 8 MiB на один создаваемый файл; это не общая квота каталога. Каждый сегмент загружает модель заново: это ограничивает время жизни и потребление памяти первой версии, ценой задержки запуска.

На границе сегмента GPU >=80°C ставит работу на охлаждение; следующий сегмент допускается при <=65°C. Во время вызова сохраняется жёсткая остановка при >=87°C. Неизвестные GPU/RAM/disk metrics приостанавливают соответствующее исполнение. Принудительные свежие проверки перед приёмом результата и после остановки контейнеров закрывают поздний перегрев/потерю метрик. Готовый сегмент при мягких 80°C сохраняется, а следующий ждёт охлаждения; при 87°C фиксация запрещена. Коды выхода после cleanup проверяются отдельно: server 0/143, остальные 0, OOMKilled=false; неизвестный exit или поздний OOM не становятся успешным переводом. Потеря permit проверяется примерно раз в секунду, с учётом ограниченного времени запросов к Docker/телеметрии; она останавливает свои контейнеры и запрещает успешную фиксацию.

Итоговый `.local/inference-spool/output/<attempt UUID>/result.json` записывается последним, после проверки контейнеров и хешей. Статусы: `completed`, `paused`, `failed`; `retryable` определяет возможность повторной попытки. Готовый файл `text.txt` либо `audio.wav` рядом с receipt — ещё не опубликованная библиотечная версия: worker обязан перепроверить lease, роль, исходный SHA, все identity fields, лимиты, хеш, просканировать и надёжно сохранить производный материал отдельно от оригинала. Папка `sandbox` содержит неподтверждённые выходы модели и не используется для чтения.

`execution.lock` удерживается весь сегмент. Backup берёт ту же эксклюзивную блокировку после остановки worker и обязательно проверяет отсутствие живых Docker-контейнеров с label `org.gargantua.inference=derived-v1`. При старте daemon останавливает и проверяет только свои помеченные контейнеры. При неизвестном cleanup удерживает барьер и не берёт новую задачу до подтверждённой остановки. После аварии хоста незавершённая попытка получает `interrupted_before_commit`; частичные файлы не принимаются, новая попытка продолжает с последнего подтверждённого в БД сегмента.

После надёжной фиксации receipt удаляются только собственные Docker-контейнеры с точным role+attempt UUID именем, проверенным label и состоянием `exited`. Не используются force, удаление volumes или образов. Если worker уже переместил receipt в `retired`, используется совпадающий документ оттуда. Повторная очистка подтверждённых остатков выполняется при старте. WAV остаётся только в библиотеке после проверки и фиксации worker; он удаляет временный spool output вместе с sandbox. В runtime остаются небольшие входные копии и журналы. Эти журналы и retired receipts в первой версии сохраняются без автоматического ограничения количества; это остающийся вопрос длительного хранения служебных метаданных, а не дублирование всей аудиобиблиотеки.

Прогон без моделей: `python -m unittest discover -s inference -p "test_*.py" -v`. Выполнены 45 тестов в Windows и в изолированном Linux runtime, плюс фактический kernel probe отказа записи >8 MiB (`EFBIG`). Другой ассистент отдельно проверил Python↔PowerShell межпроцессный backup barrier и четыре реальных Windows-сценария атомарной замены файла отдельным процессом.

Выявлена и исправлена Windows-гонка: `os.replace` может вернуть WinError5 при открытом читателем JSON, даже когда читатель запрашивает delete-sharing. Атомарная запись повторяет замену тех же fsynced bytes до 2 секунд с интервалом 25 мс для sharing/access WinError5/32/33. При длительной блокировке прежний JSON остаётся целым, временный файл удаляется; daemon продолжает попытки heartbeat и не берёт новые модельные задачи без успешно сохранённых idle/running статусов. Проверка живого daemon удерживала файл 3,5 секунды: процесс сохранил PID и восстановил свежий idle после освобождения. PS lifecycle читает коротким FileStream с delete-sharing, stop-флаг пишет с bounded retry, старые журналы переносит в history перед новым запуском.

Профиль включает SHA256 `protocol.py`, `container_worker.py`, `executor.py`; изменение поведения не может сохранить прежний профиль молча. После отдельного ревью изменения выполняется release-шаг `python inference/freeze_profiles.py`, затем `--check`. Daemon не пересоздаёт доверенный профиль автоматически. `providerRecipeSha256` считается Python и экспортируется готовым: другой язык не должен пересчитывать его после собственной нормализации JSON чисел, например `1.0`→`1`.

Реальная цепочка дважды проверена отдельно на disposable PostgreSQL/library с настоящим ClamAV, второй раз после Windows-исправления: авторская EN-микроглава → Qwen, два сегмента → отдельная RU-публикация → автоматически Piper, два сегмента, 8,475 секунды PCM. Node-обработчик был остановлен после первого checkpoint и запущен новым процессом; первый выход остался побайтово тем же. Идентичные и логически повторные запросы переиспользовали job; все хеши оригинала остались прежними. После теста не осталось ни живых, ни завершённых модельных контейнеров. Это техническое доказательство цепи и восстановления, не оценка целого романа и не прослушивание голоса.

Повторяемая процедура: `scripts/derived-model-fixture.py setup`, затем `seed`, после внешнего выделения единственного тяжёлого слота `run --checkpoint-stop 1`, новый `run` без лимита и `verify`. Запуск моделей дополнительно требует `GARGANTUA_EXCLUSIVE_MODEL_SLOT=1`. Фикстура строго ограничена отдельным DB-host `gargantua-s5-queue-db`, пустой БД и пустой library при seed; production DB/книги не монтируются. Контейнеры и volumes сохраняются для отдельной проверки backup/restore; очистку остальных проектов этот helper не поддерживает. Итоги и образцы: `.local/s5-queue/<runToken>/reports/`.
